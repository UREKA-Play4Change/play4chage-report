\chapter{Resultados} \label{cap:resultados}

Este capítulo apresenta os resultados concretos do projeto Play4Change em três dimensões complementares: a demonstração dos fluxos funcionais do sistema; as métricas de desempenho e a infraestrutura de observabilidade instrumentada; e os mecanismos que garantem a qualidade pedagógica e a segurança das questões geradas por inteligência artificial.

% ─────────────────────────────────────────────────────────────────────────────
\section{Demonstração do Sistema} \label{sec:demonstracao}

O Play4Change é composto por três interfaces: a aplicação móvel (Kotlin Multiplatform + Compose Multiplatform para Android e iOS), o painel de administração web (React~18 + Vite + TypeScript) e o servidor REST (Spring Boot 3.2, Kotlin, JVM~21). A infraestrutura é orquestrada por Docker Compose com oito serviços: PostgreSQL~16 com pgvector, MinIO, Playwright Scraper, Unstructured.io, Spring Boot, Nginx, Prometheus e Grafana; o módulo de IA (LangChain4j + Mistral) é invocado como API externa, sem contentor próprio.

Os mecanismos internos de cada fluxo --- autenticação por \textit{magic link}, geração assíncrona de tópicos, atribuição de tarefas, remediação adaptativa e tutoria com IA --- estão descritos em detalhe no Capítulo~\ref{cap:desenvolvimento} e não se repetem aqui. Esta secção regista, em vez disso, a evidência de que cada objetivo operacional (Capítulo~\ref{cap:intro}) está de facto concretizado no sistema implementado; para uma demonstração passo a passo do sistema em funcionamento, ver o guia de execução entregue em separado.

\section{Métricas de Desempenho} \label{sec:metricas}

\subsection{Arquitetura de Observabilidade} \label{sec:observabilidade}

O sistema implementa uma pilha de observabilidade alinhada com três pilares --- métricas, logs estruturados e alertas. As métricas são expostas pelo Spring Boot Actuator em \texttt{/actuator/prometheus} e recolhidas de 5 em 5 segundos pelo Prometheus (retenção de 7 dias), com avaliação das regras de alerta a cada 15 segundos e consulta via PromQL no Grafana, com dashboards provisionados automaticamente.

\section{Qualidade das Questões Geradas} \label{sec:qualidade}

A qualidade das questões geradas é garantida por seis mecanismos complementares que actuam em camadas sucessivas, assegurando que apenas questões válidas, distintas e seguras chegam ao utilizador.

\subsection{Engenharia de Prompts e Reutilização Adaptativa} \label{sec:prompt-engineering}

O sistema implementa três templates de prompt com propósitos distintos, em que a separação entre \texttt{SystemMessage} (instrução) e \texttt{UserMessage} (dados) é explícita e tipada, cumprindo o princípio de prevenção de injeção de prompt (§\ref{sec:xss}).

O contributo mais original do sistema, do ponto de vista da eficiência de custos de API, é a reutilização de ramos adaptativos: em vez de gerar um novo ramo para cada utilizador que falha, o sistema pesquisa a base de dados vectorial por contextos semanticamente semelhantes (pgvector IVFFlat, similaridade coseno), decidindo entre três estratégias por limiar de similaridade (Tabela~\ref{tab:rag-reuse}, Secção~\ref{sec:recuperacao} do Capítulo~\ref{cap:desenvolvimento}).

O prompt de geração de tarefas do percurso principal instrui o modelo a produzir 4 opções com a resposta correta sempre no índice 0 (baralhado antes de exibir), a limitar cada tarefa a 5–15 minutos, e a garantir progressão lógica; quando o número de tarefas válidas é inferior ao pedido, um \textit{schema reminder} é injetado e o modelo é invocado uma segunda vez.

\subsection{Deduplicação Semântica com pgvector} \label{sec:dedup-semantica}

A deduplicação semântica (§\ref{sec:armazenamento}) previne que o mesmo conceito seja ensinado duas vezes no mesmo módulo. Usa o operador de distância coseno \texttt{<=>} do pgvector (IVFFlat): se a similaridade do \textit{embedding} de uma nova tarefa face a uma existente ultrapassar 0,90, a tarefa é descartada e o contador \texttt{ai.dedup.duplicates\_skipped} é incrementado.

\subsection{Classificação de Padrões de Erro} \label{sec:error-pattern-results}

O \texttt{ErrorPatternClassifier} (§\ref{sec:consolidation}) aplica três regras com prioridade estrita: \texttt{TIME\_PRESSURE} (submissão após \texttt{dueAt}), \texttt{READING\_ERROR} ($|\text{diff}| \leq 1$) e \texttt{WRONG\_CONCEPT} (por omissão). Estes três valores são traduzidos, antes de alimentar o prompt do ramo adaptativo, para um \textit{enum} maior de seis valores usado do lado da IA (Secção~\ref{sec:prompting}), mapeado para instruções pedagógicas específicas (Tabela~\ref{tab:error-pattern-pedagogico}).

\subsection{Chunking de Conteúdo para Documentos Extensos} \label{sec:chunking}

Para tópicos com mais de 32.000 caracteres, o \texttt{ContentChunker} divide o texto em blocos com sobreposição de 2.000 caracteres, preservando fronteiras de parágrafo. A geração é executada chunk a chunk; se um chunk intermédio falhar, o sistema degrada graciosamente, preservando as tarefas acumuladas --- apenas o chunk~0 é crítico, e a sua falha produz \texttt{FAILED} sem recuperação.

\subsection{Sanitização de Saída da IA} \label{sec:sanitizacao-output}

Toda a saída de texto gerada pela IA é sanitizada com \texttt{Jsoup.parse(input).text()} antes de ser persistida ou devolvida ao cliente, removendo tags HTML, descodificando entidades e normalizando espaços (§\ref{sec:xss}). Os campos cobertos incluem \texttt{title}, \texttt{description}, \texttt{hint}, \texttt{options[]} e \texttt{explanationText}; esta defesa actua na camada de serviço (OWASP A03:2021) e é complementada pelo CSP Nginx e pelo auto-escaping do React JSX.

\subsection{Garantias de Qualidade das Questões} \label{sec:garantias-qualidade}

O sistema fornece seis garantias estruturais para cada questão gerada:

\begin{enumerate}
    \item \textbf{Unicidade semântica:} similaridade coseno $< 0{,}90$ com qualquer tarefa existente no mesmo módulo (pgvector IVFFlat).
    \item \textbf{Formato válido:} exactamente 4 opções, resposta correta persistida no índice~0 (baralhada antes de exibir).
    \item \textbf{Língua correta:} o prompt instrui o modelo a gerar exclusivamente na língua configurada, com \textit{gating} de idioma no \texttt{DayIndexCalculator}.
    \item \textbf{Adequação ao nível:} o prompt inclui descrição expandida do nível de audiência (\textit{Beginner}, \textit{Intermediate}, \textit{Advanced}).
    \item \textbf{Segurança:} sanitização Jsoup em todos os campos de texto; input do utilizador nunca interpolado em strings de prompt.
    \item \textbf{Resiliência a falhas do modelo:} \textit{schema reminder} automático, abandono gracioso se o resultado final for zero tarefas válidas, e circuit breaker contra cascata de falhas.
\end{enumerate}
